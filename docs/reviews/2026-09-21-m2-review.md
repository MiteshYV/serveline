# M2 review — 21 September 2026

> Two independent review passes over commit c52bb87, after the design's acceptance criteria had passed in
> a browser against the scripted mock. Findings reproduced as delivered; fixes in the commit that follows.

## Spec fidelity and security

**Findings (most severe first)**

1. **HIGH · PII in prompt** — `src/voice/tools.ts:248` stores the caller's spoken address as `label: text`; `src/voice/loop.ts:173` (`a.label ?? a.area`) then puts that line into the system prompt on the caller's next call ("Saved addresses: Indiranagar 12th main, near the metro → <id>"), and `tools.ts:231` returns it in the `use_saved_address` tool result (LLM request body). Build Spec §5.5/§10 and the design allow labels only; `prompt.test.ts` and `tools.test.ts:211-222` only ever see seeded `'Home'` labels, so the leak is untested. Fix: `label: null` (or a fixed `'Spoken address'`), `line1: text`; in `loadProfile` and `use_saved_address` fall back to `area ?? 'saved address'`, never to `line1`; add a `voice_rough` row to `prompt.test.ts`.

2. **HIGH · profile write without consent** — `src/voice/tools.ts:277-294` and `loop.ts:449` call `placeOrder` with no `order_fulfilment` consent check, unlike the web checkout (`app/(customer)/r/[slug]/checkout/actions.ts:197`). For a customer row with no consent (seeded 0008/0009 via the simulator; any caller via the service token later) an order is created and `upsertCustomerRestaurant` writes a `customer_restaurant` profile row (`source`, `first_channel`) — Build Spec §10. `call/page.tsx:36` claims `place_order` refuses `consent_required`; nothing does. Fix: the same `getConsent` + `hasValidConsent(view, 'order_fulfilment')` → `refuse('consent_required')` in `place_order`, and skip `parkOrder` when it fails.

3. **MEDIUM · read-back bypass (address)** — `src/voice/loop.ts:180` pre-sets `session.addressId = addresses[0]?.id`, so `place_order {fulfilment:'delivery'}` succeeds without `use_saved_address` ever being called; `loop.test.ts:236-243` demonstrates it ("delivery please" → order to `home.id`, no label read back). Build Spec §5.2 requires the last-used label read back for confirmation; only the prompt asks for it. Fix: do not pre-set `addressId`; make `use_saved_address`/`capture_rough_address` the only setters so an unconfirmed delivery returns `address_required` and the model asks (the prompt already lists label → id).

4. **MEDIUM · parked handoff order behaves like a placed order** — `src/voice/loop.ts:445-461` runs the full `placeOrder`: UPI link created and SMSed when COD is off, `order_confirm` SMS sent, and `customer_restaurant.usual_order` overwritten (`place-order.ts:177-186`). The caller hears "connecting you to the restaurant" then gets "order confirmed, pay here" for an order the counter may cancel, and their next greeting offers the abandoned cart as "same as last time" (verifier saw this with Arjun). Build Spec §5.2 refreshes `usual_order` only "if the order completes". Fix: `parked: true` on `CallContext`; `placeOrder` skips the payment link, both SMS and the `order:` block of the upsert when set.

5. **MEDIUM · "same as last time" is not the same order** — `src/voice/loop.ts:200` maps usual-order lines to `itemName` only; the greeting prices with variants/options (₹300) but the prompt says "Filter Coffee × 2", the model re-adds the base item, and the order charges ₹255. Fix: include `variantName`/`optionNames` in the summary name, and pre-seed `session.seenItemIds`/`searchResults` with the stored usual-order ids (or expose them in the prompt) so `add_to_cart` can carry the stored `variantId`/`optionIds`.

6. **LOW-MEDIUM · vendor error text in logs** — `src/voice/loop.ts:355` logs `error.message`; `gemini.ts:89-98` returns the body's `error.message` and `anthropic.ts:86` passes the SDK's `APIError.message` (which embeds the response JSON), so a 400 validation message can quote request content — contrary to the comment at `loop.ts:354`. Fix: log `error instanceof LlmError ? \`${error.provider} ${error.status ?? 'network'}\` : error.name`.

7. **LOW · phone number on a fifth table** — `src/voice/loop.ts:237` / `calls.ts:64-90` store `call_turn.text` unsanitised, so a spoken number lands outside the four tables (CLAUDE.md). Fix: `text: sanitiseCallerText(turn.text)` at `appendTurn` (the review screen loses nothing M4 needs), or record the departure in the design.

8. **LOW · `handoff_reason` polluted** — `src/voice/loop.ts:408,419` write `hangup` / `simulator_hangup` / `pagehide` / `customer_done` into `call.handoff_reason` on `completed`/`abandoned` calls; the list page renders it as a handoff reason and §12 metrics will read it. Fix: pass `handoffReason` only for `handoff`/`cap_transfer` outcomes.

9. **LOW · auth scope** — `app/api/v1/voice/lib.ts:24,41`: the service token is global (not "scoped to an outlet", §5.6) and can post turns into any live customer mic call; a customer cookie can open unbounded `session-init`s (call row + LLM spend each, 24 × 1000-char turns) with no rate limit. Fix: refuse `liveCall` for a service caller when `session.transport === 'browser' && session.customerId`; leave a `// ponytail:` for per-customer rate limiting before a real key is set.

10. **LOW · mock never exercises the read-back path** — `src/adapters/llm/mock.ts:234-237` calls `place_order` on "pickup"/"delivery" alone, so `loop.test.ts` never covers get_cart → yes → place_order that the prompt mandates; test-policy only, but acceptance 1 is asserted through it.

Verifier's fixes (`notes` on parked orders, `usualOrderOf` stopping at `;`, and the `mock.test.ts` separator assertion change) are correct and the test update is legitimate.

## Design fidelity

Findings, most severe first.

**1. Console review transcript lines carry no `lang`** — `app/(platform)/agent/(console)/calls/[id]/page.tsx:80` renders `<td style={{ whiteSpace: 'pre-wrap' }}>{turn.text}</td>` with `turn.language` shown in the next column but never set as `lang`. Hindi/Kannada turns (screenshot: `जोड़ दिया। अभी तक…`) sit on an English page with no language attribute — §9 ("`lang` on any element whose content differs in language from the page"). Same in the tool-call `<pre>` blocks, which echo Hindi queries/replies. Fix: `<td lang={turn.language ?? undefined}>`.

**2. Simulator transcript lines carry no `lang`** — `calls/simulate/Simulator.tsx:151`: `<p className="m-0">{line.text}</p>`. `live.lang` is known for caller lines; the AI reply's language is not returned (`TurnResult` has no `lang`), so the fix needs a `lang` on the reply or the page-level assumption that it matches `live.lang`. Same §9 violation as 1; visible in `simulator-mid-conversation.png`.

**3. Customer transcript loses list semantics on WebKit** — `call.module.css:38` sets `list-style: none` on the `<ol>` (`CallClient.tsx:525`) with no `role="list"`. Safari/VoiceOver — i.e. the iPhone customer — drops list role for `list-style: none`, so the transcript reads as loose text, not "list, N items" with speaker names. The Simulator `<ol className="… list-none">` (`Simulator.tsx:146`) has the same defect. Add `role="list"`.

**4. Brand colour on a non-permitted surface** — `call.module.css:66` `.customer { background: var(--brand-wash) }` on the caller's transcript bubbles. §3.5's permitted list for `/r/{slug}` is header band, primary CTA, tab underline, *selected-row* wash, logo chip — "short on purpose". A chat bubble is not a selected row. Use `--bg-sunken`.

**5. Copy cites internal documents / milestones** (console, but still UI copy):
- `calls/page.tsx:53` — "(Ideation §10)" in the page meta.
- `calls/[id]/page.tsx:155` — "For M4's tuning loop (Build Spec §8)".
- `calls/simulate/Simulator.tsx:104` — hint ends "(M2b)"; also leaks the enum `customer_required` and `place_order` as user copy.

**6. Transcripts at `--lh-ui` (1.45), not `--lh-body` (1.60)** — §4.2 names transcripts as body prose. Console review transcript inherits `.table { line-height: var(--lh-ui) }` (`console.module.css:83`); Simulator `<p className="m-0">` inherits `body` 1.45. Floor is met, token is wrong; Indic text in both. Customer `.line` correctly uses `--lh-body`.

**7. Console targets below 32px** — inline text links used as the row's only navigation: `calls/page.tsx:87` `<a href={/agent/calls/${r.id}}>` (date text, ~20px tall inside a 32px `td`), crumbs link (`[id]/page.tsx:63`, 12px caption), Band actions "Review this call" / "Dismiss" (`Simulator.tsx:123`, `bits.tsx:40`). §6.1 console minimum is 32×32; only the `<td>` is 32. Pre-existing console pattern, but these are new instances.

**8. Radius token misuse (low)** — `call.module.css:53` `.line { border-radius: var(--radius-3) }` (6px = buttons/inputs) on a plate/card surface; §5.2 cards/panels are `--radius-4`. Not `--radius-full`, so a token-choice nit only.

**9. Live-region chatter on the customer page (low)** — four polite regions at once: `<ol aria-live="polite">` (every line, including the caller's own), `.activity` `role="status"` cycling Listening/One moment/Speaking per turn, `note` `role="status"`, `endedTitle` `role="status"`. A screen-reader user hears each AI reply from `speechSynthesis` *and* from the live region. No `role="alert"` anywhere — that part is clean.

**Clean:** no raw brand hex; no 500/600, `letter-spacing` or `uppercase` on translatable strings (`--fw-bold` throughout, `.num` only on Latin ids/figures); no `--radius-full`; customer surface uses `--elev-1` only; customer targets all 56px (`size="counter"`, `Field.control` 56); every input has a visible `<label>`; customer `<li lang={l.lang}>` is correct; no animation at all beyond `Button`'s transform-only press (reduced-motion covered in `tokens.css`), no "listening" pulse; no webfont; no `role="alert"`; `Band tone="attention"` on send/start failures is the §7.10.1 pattern, and `Tag` "low"/"AI"/"Caller" are steel.

## Not acted on

- **Spec #10 (the mock never takes the read-back path).** The mock is a test policy; the read-back rule is
  enforced on the real model by the prompt and is exercised the first time a Gemini key is configured. Changing
  the mock would also change the acceptance conversations' turn counts for no product gain.
- **Design #7 (console links under 32px)** — fixed for the new call-list row link; the console's pre-existing
  crumb and band-action pattern is left for a console-wide pass.
